--- PÁGINA 5 ---

Estas cifras son tiempos de álgebra lineal; no dicen nada de aciertos ni de tokens.
4.2 ¿Los modos C/D usan estados latentes de un modelo?
El JSON lo genera benchmarks/run_pilot20_humanevalplus_abcd.py . Leyendo ese
script:
D: una llamada normal al modelo con el enunciado.
A: tres llamadas en cadena (análisis → contrato → código) pasándose texto.
B: un vector aleatorio pasa por matrices (sin relación con la tarea) y después una
llamada normal con el system prompt "Verify edge cases…".
C: un vector unitario fijo pasa por funciones C++/Rust (DLL de Windows); lo único
que llega al modelo es un system prompt de texto: "Axioma de Integridad Algorítmica
POLYDIM V26505 (PMTP Gen=N): Maneja estrictamente casos límite…".
Ningún modo usa estados ocultos de un modelo. C y B son "D + una frase en el
system prompt".
4.3 ¿Se puede reproducir el PILOT20?
Tal cual, no: el script necesita una clave de Cerebras leída de una base Postgres local,
DLLs de Windows y rutas E:\… . Ninguna está en el repositorio.
El JSON es coherente por dentro, pero no trae prompts ni código generado, así que
no se puede verificar tarea por tarea.
En su propio JSON, D (sin Polydim) es el mejor: 17/20 Plus con 14 910 tokens, frente a
C 15/20 con 17 382 tokens.

4.4 Reproducción del protocolo con un modelo real (Kaggle T4)
Mismo script de ellos para las 20 tareas, los prompts, la lógica de cada brazo y sus
funciones extract_python_code / evaluate_code_on_task . Cambio: Qwen/Qwen2.5-
Coder-7B-Instruct 4-bit local en lugar de Cerebras. Datos: evalplus oficial.
C y D aprueban exactamente las mismas tareas, una por una. C solo gasta +13 % de
tokens (la frase extra).
B pierde una tarea ( HumanEval/64 ) por un error de formato del bloque de código, no
por el vector.
A gasta 8,6 veces más tokens que D y no acierta más.
Conclusión: con un modelo real, el modo "Polydim" no mejora ni los aciertos ni los
tokens frente a la llamada directa.

6. Recomendaciones
1. Fijar transformers>=4.44.2,<4.48 en la receta de DeepSeek-Coder-V2-Lite (o
actualizar el código remoto).
2. En el PILOT20, comparar contra D (llamada directa), no solo contra A; y publicar
prompts, salidas y el script ejecutable sin claves privadas ni DLLs.
3. Para que el modo C sea "latente", el modelo receptor tiene que recibir estados ocultos
del emisor (por ejemplo, la memoria KV compartida, que en la ronda v4 dio 7/10 con
−76 % de tokens de entrada).
4. Llamar "ablation real" solo a un harness que ejecute modelos y tests en la misma
corrida.
7. Reproducibilidad
Código de terceros: AGT1973/POLYDIM_EinSof y AGT1973/polydim-suite , commit
47eefb7e621b1e54ef1ef0a32254f438528c8edb, clonado dentro de cada kernel.
Reintentos usados: prueba 2 = 2 reintentos (2b, 2c); pruebas 1 y 3 = ninguno.
Redacción: claude (Opus) a partir de los resultados medidos. Revisión de datos: llama-
3.3-70b aprobó todos los números después de una verificación automática contra los
resultados.
