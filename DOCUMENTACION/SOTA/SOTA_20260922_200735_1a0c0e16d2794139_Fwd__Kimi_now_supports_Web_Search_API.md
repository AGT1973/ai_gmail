Hi Builders,

*The Kimi Open Platform now offers three standalone REST APIs: Web Search
Basic, Web Search Pro, and Web Fetch.*
Web Search Pro

Web Search Pro brings targeted improvements to professional knowledge
search and factual queries: the model reads the page content first, then
picks out and returns the passages most relevant to your question. It also
returns a source authority level field, so you can evaluate and filter the
results further.

Compared with handing an entire web page to the model, Web Search Pro gives
you four advantages:

   - *More accurate answers: *less interference from navigation, ads, and
   other irrelevant content, so key information stands out.
   - *Lower token cost: *only highly relevant passages enter the context,
   which cuts wasted tokens and speeds up responses.
   - *Less engineering work: *chunking and relevance ranking are handled
   server-side, so results are ready for the model to use.
   - *Always traceable sources: *every passage keeps its title, link, and
   site, making citation and verification straightforward.

The three APIs at a glance
API Returns Best for
*Web Search Basic*
POST /v1/tools/search Titles, snippets, links and other structured
fields Showing
results, source cards
*Web Search Pro*
POST /v1/tools/search_pro The most relevant passages of page content
Web-connected
Q&A, Web RAG, agents
*Web Fetch*
POST /v1/tools/fetch The body of a given URL Page reading, research
collection
Pay per call, no charge for failures or empty results

The three APIs are independent and billed separately. You are charged only
when a request succeeds and returns a valid result or content.
